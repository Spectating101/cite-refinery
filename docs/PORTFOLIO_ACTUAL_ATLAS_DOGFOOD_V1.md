# First actual portfolio dogfood — source-bound public slice, NOT autonomous portfolio appraisal

**2026-10-23.** This is an end-to-end *mechanical* run of Cite–Refinery's actual `SemanticGraph` and `ProductWorkspace` plus a separate genuine CPU semantic-retrieval model over original GitHub documentation. It intentionally does not claim private portfolio coverage, working-product superiority, audited profits, human preference, or fully automated recommendations.

## Public repository source set

Eight exact original default-branch commit hashes and README Git blob IDs are frozen in `research_materials/portfolio_dogfood/public_source_manifest_2026_10_23.json`: Hardware Splicer, YZU Research Drive interface, Gauntlet/Blowback, Public-Good Control Plane, Live Presenter, Cite–Refinery, Invisible Ledger and Citation Engine. Only these named, public source files are retrieved and stored in the review-only output. They are **not** instructions to execute any repository code.

The source handler verifies both the GitHub Content API blob SHA and recomputes the Git blob SHA-1 from the returned exact bytes. It optionally checks the latest observed `main` GitHub Actions workflow and records whether it was executed on **the same original source commit**. Absence/failure to fetch that metadata is recorded `unknown` rather than a false CI fail or an untested proof of success.

**PRIVATE PROJECTS ARE NOT IMPORTED TO THIS PUBLIC REPO OR CI:** Policy Lab/SolarPunk, Nocturnal Oversight, Refinery, Cite-Agent, Sharpe–Terminus and the private Research Drive runtime. Those require an authorized local/private source audit; do not put their private README, manifests, discussion, data or diagnostics in a public Atlas artifact merely to make the inventory appear complete.

## What the actual Atlas run tests

1. **Source identity:** detect altered README/commit, changed source SHA and unauthorized repository.
2. **Real three-layer graph:** use `SemanticGraph.ingest_packet` to construct a source-scoped project from eight original program/repository descriptions, observed read-only CI metadata as Practical observations, and exactly one *unverified self-described research question* in the Academic map. All other article claims remain unrepresented until separately sourced and tested; missing layers mean only `NOT REPRESENTED`.
3. **Meaningful uncertainty:** maintain original-source URLs and Git SHA receipts; all qualitative inter-repo reuse relations stay `candidate`. CI metadata is a *qualified observation*, not evidence of field functionality. No `SUPPORTS` evidence approval, scientific answer, external adoption proof, commercial claim or code-execution promotion occurs.
4. **Real product projection:** use actual `ProductWorkspace.project_view` and `SemanticGraph.cluster_map/export` and check the exact record/edge preservation and three-map product surface.
5. **Actual pretrained semantic lookup:** a real local ONNX `sentence-transformers/all-MiniLM-L6-v2` model embeds the source-derived short portfolio program descriptions, without repository IDs in vector texts, and receives eight investigator-selected paraphrase queries + three declared unanswerable claims. It records exact source rank, top-3 suggestions and cosine scores but **does not automatically generate true/false answers from those scores**. These are developer-chosen tasks, *not blind gold*.

This is intentionally not the same as the frozen 1,497-record Atlas development set, nor does it silently mix development results with new source-grounded evidence.

## Side-by-side competitive baseline

**Ordinary GitHub + owner README + GitHub Actions is the primary competitor in this dogfood.** It already reveals source names, release notes, self-reported limitations and workflow statuses. If the Atlas merely assembles those facts into a graph without independently finding/qualifying additional important relationships, it has **not demonstrated competitive advantage**.

[OpenSSF Scorecard](https://scorecard.dev/) is the stronger established comparison for automated repository security, CI and maintenance signals; this dogfood does not call the Scorecard service and MUST NOT claim equal security assessment. [CodeScene](https://codescene.io/) is a further alternative for maintainability/hotspot assessment; its algorithm is not reproduced here. Scholarly and investigative alternatives (PaperQA2, OpenScholar, OpenAleph/FollowTheMoney, ORKG) remain external specialized comparators; their real cross-portfolio outputs have **not been measured**.

## Interpretation and next acceptance gate

Passing this test means we can **ingest and navigate original multi-project evidence into an actual structured Atlas** with privacy and uncertainty boundaries, and can measure whether small semantic retrieval helps navigate eight public README descriptions. It says nothing decisive about automated funding viability, market advantage, human usefulness, security posture, academic entailment or reusable functionality.

Before claiming the complete private portfolio was assessed *by Cite–Refinery*, separately authorize an Optiplex-run full corpus with all private worktrees, frozen source heads and private output; do not fabricate an Optiplex run if the remote commander quota is exhausted. The first future source-deep test should present the Atlas with both plausible and deliberately false portfolio link candidates and measure **independently adjudicated correctness, abstention, reproducible tests, and human analyst effort** against plain GitHub + a general capable model.

**Critical acceptance test:** It must distinguish `software package exists` vs `released to users`, `CI passed` vs `physical testing`, `paper/claim appeared` vs `scientific finding confirmed`, `source has similar words` vs `source proves an exact requirement`, and `not indexed` vs `no solution exists`. If it does not, classify this as a navigation/demo validation only, not intelligence-product readiness.

Repo changes are confined to a draft branch stacked on the prior intelligence tests. No current branch or private source system is modified.
