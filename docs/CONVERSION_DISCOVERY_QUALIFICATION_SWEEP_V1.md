# Cite–Refinery: four-slice discovery and qualification sweep

October 21, 2026. Successor to PR #94. Focus: broad discovery of potentially valuable, genuinely capable yet underconverted existing assets, and the barriers to using, improving or recombining them. No particular market, financial return, buyer, or complete three-layer chain is required. Funding remains an optional enabling-resource sidecar.

## Sources and actual coverage

The source universe remains the earlier non-exhaustive 63-record scholarly/official corpus with eight emergent research themes and the GitHub survey of 605 repositories across 44 topic strata.

Four stable-hash samples spanning all six implementation macros inspected 35 + 36 + 35 + 36 = **142** repository listings. Two additional model discovery calls broadened the prior first two slices. Across these runs the model submitted **22 proposals**; **21 retained** exact-source candidate relationships and **one was rejected** because it invented an unrecognized repository ID. Its original raw response is retained in noncommitted research scratch; the committed slice holds the rejected receipt and hash.

The 21 links cite **25 distinct repository identities**. All **25** were inspected through the original GitHub API and public README, including basic source, license and test-directory metadata. Metadata does not establish that functionality works, that the project is good, or that it is underconverted. No new native accepted graph edges exist, no real project has been adopted, and no cash benefit is claimed.

## Independent source-function evidence

A bounded original-code experiment was performed using [GridShadow](https://github.com/Krishita17/GridShadow) at commit bbeaa5d1d1b617025c2e7c3acd4c1f4c629bd4a4, cloned into scratch. The original requirements were installed in an isolated Python 3.12 virtual environment. The unchanged upstream 15 tests passed using the original suite, covering synthetic cyber-physical graphs, power-flow toy cases and chokepoint search/recommendation.

On the unprepared host, test collection had previously been blocked because pandapower was not installed. That is a local dependency gap, **not** a failing original test. The venv run establishes a reproducible component-level baseline, NOT the proposed combined GridShadow–Jackery implementation, real energy-system control, production suitability or general high software quality.

[soypat/lneto](https://github.com/soypat/lneto) was also cloned for source inspection, but its Go compiler was not installed and no tests were run. This is **not** a failed repo test.

## Underconversion and legal-source uncertainties

A project's developer description, stars, release activity, GitHub test folder and README cannot establish high quality, absence of adoption, demand, rights or a conversion gap.

Rights questions requiring inspection include:
- [FreddyFridge](https://github.com/nadar71/FreddyFridge): no GitHub API SPDX license value in sampled metadata.
- [PantryRaider](https://github.com/Syracuse3DPrintingOrg/PantryRaider): GitHub reported NOASSERTION.
- [lindbrook/cholera](https://github.com/lindbrook/cholera): no API SPDX value.
- [Transitland Atlas](https://github.com/transitland/transitland-atlas): CC-BY-4.0 API label; attribution and data/source distinctions require review.
- Other candidates advertise MIT, Apache-2.0, BSD-3-Clause or AGPL-3.0: compatibility must be evaluated before reuse.

These are potential blockers to downstream usage, **not evidence that any of those projects is ineffective or undervalued**.

## Cross-sector qualification experiments to run next

1. **GridShadow + Jackery:** Examine the actual Jackery data entities and GridShadow's defensive simulation input contracts; test a purely offline hypothetical adapter, not household control or live grid infrastructure. Reject if interfaces or scientific interpretation do not fit. GridShadow's 15 tests do not validate this new connection.
2. **Argos logging + food redistribution:** Independently evaluate whether a chain-of-custody technique measurably improves auditability of synthetic pickup data relative to a baseline. Verify whether food organizations need it; recording hashes is not nutrition-outcome proof.
3. **Nongor + flood warning:** Original source audit, rights/privacy and authorized isolated device reliability checks before any safety-related proposition. Do not deploy experimental communications in an actual emergency.
4. **FreddyFridge + factorysemantics MES:** Resolve the absence of a detected code license, then check entity and workflow interoperability against an actual food-expiry/redistribution requirement.
5. **Within-research effective coverage analogy:** Examine vaccination biological response versus heat-warning behavioral response as a *measurement analogy*, not a transfer of epidemiological thresholds.
6. **Additional open-ended discovery:** Expand beyond the same eight scholarly/official themes, and independently score novel cross-domain links against strong general AI and human reviewers.

The key missing evidence is still independent technical capability evaluation, actual adoption/usage, barriers and why an apparently good project has not converted. A promising new use that already exists elsewhere may be useful, but is not a novel discovery. A low-star project may be high quality or poor quality; stars do not resolve that question.

## Architecture and reproducibility

The canonical Cite–Refinery investigate command now supports discover-conversions and qualify-conversions. The latter consolidates existing open-corpus source-first proposed relationships, original GitHub metadata and pinned original source test receipts into a read-only evidence-quality queue.

To reproduce, supply four discovery JSON files, two original-repo audit files, the original-source test-receipt file, and new Markdown/JSON output paths as documented in the CLI help. No new executable entrypoint, domain-specific engine, fourth conceptual layer, graph promotion, proprietary takeover, marketplace order, funding application or realized conversion claim.

The small optional funding catalog from #94 (NLnet, GitHub Sponsors, Open Collective, Grants.gov, FINDIT and unresolved CSG) is preserved. This qualification step does not treat grants or money as prerequisites.

**Success criterion for the following phase:** verify one project is technically good in its relevant scope, establish a real underconversion barrier with independent usage evidence, and demonstrate a reproducible novel use or recombination that overcomes that barrier. **The current 21 candidates have not crossed that threshold.**
