# Problem Commons Conversion Research V0.1

Date: 2026-09-08

Status: **conversion research / empirical program**

This document shifts the Problem Commons program from architecture expansion toward external conversion: real problem owners, real solvers, real contributions, funding/resource paths, repeat institutional use, and eventually paid program infrastructure.

The figures below are source observations or explicit pilot targets. Pilot targets are not market forecasts.

## Core conversion thesis

Problem Commons should not attempt to replace every downstream project, grant, challenge, capstone, volunteering, or procurement platform.

Its differentiated conversion layer is:

`messy real-world condition → evidence-bounded Problem → solver-ready work → appropriate downstream opportunity → contribution → verified result → reuse/outcome`

The commercial/institutional object is therefore not merely a public catalog. It is infrastructure for **turning unresolved demand into governed, trackable work**.

## External demand evidence

### 1. Work-integrated learning is already a large operating category

Riipen currently presents itself as a project-based learning platform connecting educators, employers, and learners and reports:

- 53K+ employer projects;
- 760+ educational institutions/training providers;
- 318K+ learner experiences;
- 20.9M+ hours of applied learning.

Source: https://www.riipen.com/

Riipen's June 2026 Career Connected Campus launch explicitly targets institution-wide infrastructure for embedding authentic employer projects across majors/programs.

Source: https://www.riipen.com/news-press/new-enterprise-solution-for-colleges-and-universities-embeds-unique-employer-projects-across-majors-and-academic-programs

Its Level UP program is a particularly useful economic benchmark: a government-backed paid work-integrated-learning program in which eligible students complete a 60-hour real employer project and receive a CAD 1,400 stipend on successful completion.

Source: https://help.riipen.com/en/articles/11140829-level-up-faqs

Interpretation for Commons: paid, bounded, real external problem work is already an established behavior. Commons should compete upstream on problem quality/evidence/governance and downstream on longitudinal problem/reuse state, not merely imitate employer-project listings.

### 2. Highly scoped skilled contributions are usable by nonprofits

Catchafire describes 150+ ready-to-use project types, generally 5–50 hours, with explicit skills, deliverables and impact statements. It also supports one-hour calls as a smaller entry unit. Nonprofit access may be foundation-sponsored.

Source: https://help.catchafire.org/en/articles/8380963-what-is-catchafire-and-how-do-i-join

Interpretation for Commons: Project Brief quality and effort bounds are economically/operationally important. A broad Problem must decompose into contribution units people can actually accept.

### 3. Institutions pay for social-impact program operations

Submittable reports 165K+ programs supported and more than USD 10B in funds managed through its grants-management product. Its wider social-impact product spans grants, scholarships, in-kind donations, relief funds, awards, financial gifts and sponsorships.

Sources:
- https://www.submittable.com/solutions/grants
- https://explore.submittable.com/

Interpretation for Commons: the durable institutional revenue opportunity is plausibly workflow/program infrastructure rather than extracting a percentage of grant awards.

### 4. Open-innovation programs pay for problem-solving at much higher ticket sizes

InnoCentive/Wazoku currently lists live challenges with cash awards ranging from USD 10,000 to USD 800,000 in the sampled September 2026 listings. Wazoku reports a 1M+ expert-solver community and enterprise programs across R&D, sustainability, procurement and strategy.

Sources:
- https://www.innocentive.com/challenges/
- https://www.wazoku.com/partners/

Interpretation for Commons: mature, bounded Problems can eventually graduate into prize/open-innovation channels, but Commons should not force every Problem into a competition.

## Conversion ladder

### Lane A — internal/external pilot proof

Target object: YZU USR / social-engagement course / local organization.

Offer:

- curate 3–5 real Problems;
- turn each into solver-ready Project Briefs;
- give student/research teams bounded contribution paths;
- track evidence, attempts, outputs, review and owner feedback;
- produce a reusable end-of-cycle case report.

Primary conversion value: external proof, owner feedback, solver data, portfolio legitimacy.

Relative priority: **10/10**.

### Lane B — repeat institutional project pipeline

Target object: course/program/USR office/research center.

Offer:

- problem intake;
- curation;
- project matching;
- reviewer/owner workflow;
- outcome/reuse reporting;
- institution workspace.

Primary conversion value: repeat usage and eventual institutional payment.

Relative priority: **9/10**.

### Lane C — paid/stipended microprojects

Target object: sponsored student work, RA-style projects, corporate/USR sponsorship, philanthropic project pools.

Offer:

- bounded 20–80 hour project opportunities;
- explicit compensation/resource state;
- deliverable and evaluator;
- owner acceptance/receipt.

External benchmark: Riipen Level UP demonstrates a 60-hour / CAD 1,400 paid project model.

Primary conversion value: proves labor can be economically supported instead of relying on volunteering.

Relative priority: **8/10**.

### Lane D — civic/open-innovation distribution

Target object: g0v/hackathons, Presidential Hackathon, InnoCentive-style challenge channels, other civic-tech/open-innovation programs.

Offer only Problems that are mature enough to become a bounded challenge with real evaluation criteria.

Primary conversion value: external solvers, visibility, funding/prizes, institutional contact.

Relative priority: **6/10 now; higher after pilot evidence**.

### Lane E — funding/resource routing

Target object: grant, CSR, in-kind, expertise, equipment, partnership programs.

Commons owns the project need. Public-Good qualifies external resource opportunities. A qualified match remains a candidate until verified application/commitment evidence exists.

Primary conversion value: turns viable work into funded/supported work.

Relative priority: **6/10 supporting lane; not the product center**.

### Lane F — procurement / paid institutional implementation

Target object: municipality, public institution, university, NGO network, company.

Only after real pilot evidence.

Primary conversion value: highest direct revenue/adoption quality, but longest trust/authority path.

Relative priority: **3/10 today; potentially 9/10 at maturity**.

## Pilot success gates

These are experiment thresholds, not forecasts.

### Gate 1 — problem-owner conversion

Within the first structured pilot cohort:

- >= 3 independent problem owners;
- >= 10 candidate Problems received;
- >= 5 survive owner/reviewer curation into solver-ready state.

Failure signal: owners cannot provide enough context/access for useful projects or disagree with the resulting formulation.

### Gate 2 — solver conversion

Across solver-ready Problems:

- >= 20 independent solver sessions;
- >= 5 serious attempts;
- >= 2 externally useful/accepted outputs.

Failure signal: people understand the Problems but do not choose work, or need heavy founder coaching to progress.

### Gate 3 — repeat use

- >= 1 problem owner supplies a second Problem or continuation;
- >= 1 educator/program manager asks to run another cohort or integrate another project.

Failure signal: first use is interesting but not operationally worth repeating.

### Gate 4 — economic support

- >= 1 contribution is stipend/grant/sponsor/contract/in-kind supported;
- no ambiguous resource match may be counted as funding.

Failure signal: serious work remains structurally dependent on unpaid labor.

### Gate 5 — compounding

- >= 1 later Problem searches for and reuses a capability produced by an earlier Problem;
- measure search + adaptation time vs rebuild estimate.

Failure signal: the Refinery layer records artifacts but does not reduce later work.

## Metrics to instrument

Primary:

- candidate → solver-ready survival rate;
- curator minutes per surviving Problem;
- problem-owner agreement/reframe rate;
- Project Brief view → serious attempt rate;
- serious attempt → accepted/useful output rate;
- repeat-owner rate;
- repeat-program/institution rate;
- resource candidate → verified application → commitment rate;
- later-problem capability reuse rate;
- net hours saved by reuse;
- real outcome/adoption count (kept separate from activity).

Do not optimize vanity metrics such as raw registered users, raw Problem count, page views, or number of funding opportunities indexed until the core conversion rates are credible.

## Product/revenue hypothesis after proof

Keep the public Commons open where practical. Monetizable institutional surfaces may include:

- private problem intake/workspaces;
- institutional project/program management;
- curated problem production;
- verified reviewer workflows;
- solver/project cohort administration;
- resource/funding qualification workflows;
- evidence/outcome reporting;
- cross-project capability/reuse analytics;
- self-host/on-premise deployment where required;
- later procurement/pilot administration support.

Do not build payment custody, generic grant-database duplication, reputation markets or broad consumer monetization before repeat institutional use is demonstrated.

## Immediate next conversion experiment

The fastest credible experiment is **YZU-first but not YZU-only**:

1. select 3 existing YZU/USR/local Taoyuan problem owners or project teams;
2. take 1–2 unresolved real conditions from each;
3. curate 5–10 Commons Problems;
4. generate Project Briefs suitable for a class, research assistant, independent student team or technical contributor;
5. recruit 20 independent solvers with minimal founder coaching;
6. return accepted outputs to the problem owners;
7. record whether any owner/course/program requests another cycle;
8. only then pitch Commons as repeat institutional infrastructure.

The objective is not a polished launch. It is to produce the first evidence that a real institution can repeatedly turn messy external demand into useful governed work through Commons.
