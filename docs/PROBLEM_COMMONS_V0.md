# Problem Commons V0

The V0 treats the **problem** as the primary public object. Cite-Refinery remains the capability/execution/reuse machinery inside a wider loop; this prototype deliberately does not merge Nocturnal, Public-Good, Cite-Agent, Refinery, or Citation Engine into one database.

## Ownership boundary

| Object/state | Primary owner |
|---|---|
| observation, matter history, correction, later outcome | Nocturnal |
| diagnosis, constraints, intervention/authority boundary | Public-Good |
| scholarly/empirical claims, evidence, gaps | Cite-Agent |
| reusable capabilities, implementations, runs, experiments | Refinery / Cite-Refinery |
| provenance / basis / authority / receipt primitives | Citation Engine |
| living problem identity, publication state, decomposition, attempts, outcome references | Problem Commons |

## V0 invariants

1. A raw observation is not automatically a public problem.
2. A problem cannot become `verified` or `open` without evidence, a steward, an unresolved core, an authority boundary, and at least one success criterion.
3. Publication warnings surface missing actors, constraints, knowledge frontier, capability frontier, decomposition, and unreviewed evidence.
4. Attempts attach to a living problem and may target explicit subproblems; an attempt is not automatically a solution.
5. Real-world outcome is distinct from successful execution or prototype completion.
6. A resolved problem can reopen when later evidence shows recurrence.
7. Public browsing should expose verified/open states; candidate/researching material is curator-side by default.
8. Consequential action remains outside this service and requires competent human/institutional authority.

## Initial lifecycle

`candidate → researching → verified → open → partially_resolved / piloting → deployed → monitoring → resolved`

Side paths allow `reframed`, `retired`, `invalidated`, and reopening after recurrence.

## What the public page must answer

A solver should be able to determine, without talking to the original curator:

- Is this condition real enough to work on?
- Who is affected?
- What is already known?
- What is disputed or missing?
- What capabilities already exist?
- What still needs doing?
- Where can I contribute at my skill level?
- What would count as success or falsification?
- Who has authority to implement anything consequential?
- What attempts already exist?
- What happened after prior attempts?

## V0 evaluation

The first empirical test is not traffic or registrations. Curate 5-10 real problems and measure:

- curator time from messy source material to reviewable packet;
- factual corrections after domain review;
- number/severity of reframings;
- independent solver comprehension;
- whether an outsider can identify a useful contribution without direct curator coaching;
- serious attempt rate;
- percentage of work that reuses existing evidence/capabilities;
- problem-owner usefulness rating;
- whether any attempt reaches a real pilot/outcome.

If high-quality packets require unsustainably large expert effort, outsiders still cannot tell where to contribute, or owners will not permit realistic implementation paths, the concept should be narrowed or pivoted before marketplace/network features are built.
