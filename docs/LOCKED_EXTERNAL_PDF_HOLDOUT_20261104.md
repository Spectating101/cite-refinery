# First prospective no-hint PDF row-region holdout — November 4, 2026

**Decision: HOLD. The conservative original-PDF ruled-source fallback has excellent conditional precision in a small scored subset but very poor recall. It is NOT a production table extractor.**

## Ordering and scope

The selected file manifest was committed in Atlas commit `818d84f` **before downloading or examining any of the 16 selected PDFs**. Source: the external Camelot software fixture repository at pinned upstream commit `92777b852e00933a5c4b9ba642601784604356cd`. Eight documents were predeclared stress cases (merged row/column spans, missing values, rotated/vertical headers, background lines, image/empty files and multiple tables); eight more were selected by a deterministic SHA-256 filename hash seed. The two Camelot fixture PDFs used in previous development (`health.pdf` and `foo.pdf`) were excluded.

Research Drive's **no-operator-crop/no-hint** `optional_pdf_blind_scan` was frozen in Research Drive commit `2f5bd7f` before any of those original files were downloaded. The scanner groups explicitly drawn horizontal PDF line and filled rectangle strips by a fixed geometric policy; it cannot infer text-only rows, column meaning, multi-tier headers, paper-wide table recall, or OCR. Baseline source scans on earlier, already-seen development documents and synthetic vector PDFs were allowed before the engine freeze. **No threshold or source selection changes were made after seeing holdout results.**

This is a *prospectively held-out, self-administered software test*, not a genuinely independent blind study or statistically representative real-world document sample. An independent second human reviewer did not participate.

All 16 of 16 PDF first pages were attempted with original file SHA-256 recorded.

## Third-party reference-row scoring

After the first-pass scan was fixed and saved, the matching upstream Camelot `tests/data.py` and test assertions were retrieved at **the same pinned repository commit**, with original SHA recorded. Six of the 16 selected documents contain directly identifiable published upstream test DataFrame row assertions. All expected rows in those six cases were scored with **strict NFKC/casefold/whitespace-normalized entire-row string equality**. Duplicate rows are counted with multiset matching, not unlimited reuse. Source predictions and reference rows were not generated by the same Research Drive parser.

| Reference-supported fixture | Upstream expected rows | Exact row matches | Missed rows |
|---|---:|---:|---:|
| `multiple_tables.pdf` | 10 | 10 | 0 |
| `vertical_header.pdf` | 17 | 0 | 17 |
| `background_lines_1.pdf` | 8 | 0 | 8 |
| `edge_tol.pdf` | 24 | 0 | 24 |
| `column_span_2.pdf` | 11 | 0 | 11 |
| `detect_vertical_false.pdf` | 37 | 0 | 37 |
| **Six reference-supported first pages** | **107** | **10** | **97** |

The six reference-supported pages contain **10 predicted row bands**; all match exactly, so conditional precision = **10/10 = 100%**, and recall = **10/107 = 9.35%**. This 100% conditional precision MUST NOT be claimed as general PDF precision: the **other ten documents have no comparable independent test-row oracle in this evaluation**, and their **58 additional candidate row bands remain unscored**. The external reference rows are Camelot's prior published parser-test expectations, **not** a fresh independently transcribed original PDF truth set or independent human approval. Some upstream test fixtures explicitly require special parser flags or report complex/merged text structures, so strict full-row text equality is a conservative but narrow metric.

There was no post-hoc removal of `vertical_header.pdf`, `column_span_2.pdf`, `background_lines_1.pdf`, image/empty documents, or any other case. All abstentions stay in the 16-page denominator.

## Why the result matters

The previous hand-bounded vector table on arXiv had **15/15 words accounted for**, and a new hand-bounded filled-rectangle Camelot health fixture accounted for 190/190 printed words within a selected page slice. Those source-geometry witnesses were correct **under supplied crop/column bounds**. In contrast, the frozen no-hint row scanner recognized only six of sixteen new pages and missed most independently expected rows. This is evidence that **finding source tables, inferring rows on non-ruled structures, and handling merged/rotated headers** remain unsolved. Strong hand-scoped word matching does not imply reliable automatic extraction.

**Next work should be openly labeled as post-holdout engineering, not a revised blind result**: integrate or benchmark Camelot's own lattice/stream/network/hybrid and suitable existing alternatives for unsupported layouts; use independent original source adjudication; then preregister a *new* unseen test set before recalculating precision/recall. Do not retune `2f5bd7f` and overwrite this holdout's 9.35% recall.
