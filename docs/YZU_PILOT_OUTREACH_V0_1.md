## Smallest pilot offer

Do **not** pitch a new platform deployment.

Pitch a bounded conversion experiment using work YZU already performs:

> YZU already collects field needs and runs USR/social-participation projects. We would like to test whether a structured Problem layer can make a small sample of those needs easier to confirm with the owner, decompose into student/research/project work, match to appropriate resources, and carry forward with evidence of what happened.

### Ask from YZU

- nominate 3 willing problem owners / USR teams / field partners;
- provide 5-10 existing unresolved needs or current listings;
- allow us to return a short owner-review pack before any solver/project work;
- identify an appropriate YZU reviewer/contact for each surviving Problem where needed.

Cycle 1 requires:
- no software integration;
- no public launch;
- no participant-level sensitive data;
- no commitment to fund or staff any generated project;
- no transfer of institutional authority to Problem Commons.

### What Commons returns

For each submitted need:

1. a source-linked, non-public candidate Problem;
2. an owner-facing review pack asking whether the need is current/correct and what constraints are missing;
3. if owner-approved, 1-3 bounded Project Briefs containing work scope, skills, effort, expected output, reviewer, funding/volunteer state, and authority/safeguarding boundaries;
4. a record of any solver attempts and owner/reviewer acceptance;
5. an end-of-cycle report showing survival/reframe rate, curation cost, useful outputs, unresolved blockers and any reuse/continuation.

## Demonstration case already prepared

A public YZU field-matching listing for `永豐靈糧堂課後輔導班` has been reconstructed as a **candidate only**.

The converter deliberately surfaced unresolved points before treating the listing as a Project:
- whether the need is still current;
- the actual tutoring/capacity bottleneck;
- what outcome the owner prioritizes;
- which collaboration mode the owner can supervise;
- safeguarding/access requirements;
- funding/compensation state;
- a geography inconsistency between the page heading and the listed street address.

No owner endorsement is inferred from the public listing and no child-facing work is opened before owner/safeguarding review.

## First-contact email — English fallback

Subject: Small YZU USR/Field-Matching Pilot — Turning Existing Needs into Solver-Ready Projects

Dear Director Wang and the Sustainability Development and Social Responsibility Center,

I am Christopher Ongko (王新福), a Yuan Ze University student. I am currently testing an experimental system called Problem Commons. The goal is not to replace YZU's existing USR or field-matching systems. It is to test a missing middle layer: whether an existing field need can be confirmed with the problem owner, structured with its evidence and constraints, decomposed into bounded student/research projects, and then tracked through useful outputs and owner feedback.

YZU already has the difficult parts: field partners, USR/USR Hub teams, student social-participation mechanisms, and sponsorship/resource channels. I would like to run a very small no-integration pilot using needs YZU already has.

The proposed first cycle would use 3 willing problem owners/USR teams and roughly 5-10 current needs. We would first return a short owner-reviewable Problem Packet. Only owner-confirmed needs would be converted into Project Briefs for students/researchers. No public launch, software integration, sensitive participant data, or funding commitment is required for the first cycle.

I have already reconstructed one public YZU field-matching listing as a non-public test case. Rather than treating the listing as established truth, the system flags what still needs owner confirmation, including whether the need remains current, the actual capacity bottleneck, desired outcome, safeguarding/access constraints, and funding/compensation state.

If useful, I can show the current case and owner-review workflow in a 15-20 minute demonstration, after which the Center can decide whether the experiment is worth continuing.

Best regards,
Christopher Ongko / 王新福
Yuan Ze University

## 15-minute meeting agenda

1. **2 min — Existing YZU workflow**
   - Center explains how a field/USR need currently moves from intake to student/team matching.
2. **4 min — Live conversion example**
   - show raw public listing;
   - show what Commons preserves vs. refuses to assume;
   - show owner review pack.
3. **4 min — Solver-ready result**
   - show how an owner-approved need becomes 1-3 Project Briefs;
   - show effort/skills/output/funding/authority fields.
4. **3 min — Pilot selection**
   - identify 3 owners / 5-10 needs that are safe and practical to test.
5. **2 min — Success/failure gate**
   - agree what would make the pilot useful enough to repeat and what would make it not worth continuing.

## Questions to ask the Center

Do not spend the meeting explaining the ontology. Ask:

- Where does the current field-matching/USR process lose the most time: clarifying needs, finding students, supervising work, funding, or reporting results?
- How often are submitted needs stale, too broad, underspecified, or hard to match?
- Which current needs repeatedly carry over because no suitable team picks them up?
- What information does a teacher/student team normally need before committing?
- What evidence/results are hardest to collect for USR reporting or impact evaluation?
- Which three problem owners would be easiest to ask for a 10-minute review of a reconstructed need?
- What types of student work can use existing course/USR/social-participation funding, and what cannot?

## Decision rule after first meeting

Proceed only if the Center can identify at least:
- 1 willing problem owner;
- 2 real unresolved needs;
- a legitimate path for one student/research contribution.

Do not interpret general encouragement as adoption.

A real conversion event is one of:
- owner agrees to review a specific Problem;
- Center supplies a new raw need;
- Center names a program/course/team for a specific Project Brief;
- owner asks for continuation/reframe;
- a real resource/funding/support path is initiated.
